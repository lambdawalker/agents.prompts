# Go Infra Composer deploy wizard: flow and interface study

Source: [`go.infra.composer` main at `ff065d4b853c7b0a2981da342767a569f18633fb`](https://github.com/lambdawalker/go.infra.composer/tree/ff065d4b853c7b0a2981da342767a569f18633fb), inspected 2026-11-27. This study concerns the separately versioned `deploycli` module and its browser wizard, not the root `infra-compose` simulator. The current implementation is the evidence below; the final section extracts reusable prompt requirements rather than asserting that other wizards already implement them.

## What the CLI deploys

A consuming repository supplies a versioned `deploy.json`, a Pulumi program, and thin launchers pinned to the CLI. The manifest declares the repository, feature, Pulumi project/directory and stack naming, build inputs, optional project inputs and GitHub configuration, output allowlist, and artifact labels. It does not carry cloud credentials, account IDs, or executable shell snippets. The manifest's input composition resolves derived values and rejects unknown or cyclic dependencies before prompting. The default terminal action is deploy; a browser session without an explicit action presents cards and defaults to Preview. CI requires explicit target arguments and a separate apply approval. [CLI guide](https://github.com/lambdawalker/go.infra.composer/blob/ff065d4b853c7b0a2981da342767a569f18633fb/deploycli/README.md) · [action selection](https://github.com/lambdawalker/go.infra.composer/blob/ff065d4b853c7b0a2981da342767a569f18633fb/deploycli/cmd/infra-deploy/interaction.go#L116-L160) · [flags and checks](https://github.com/lambdawalker/go.infra.composer/blob/ff065d4b853c7b0a2981da342767a569f18633fb/deploycli/cmd/infra-deploy/main.go#L285-L374)

## Observed user journey

| Stage | Current behavior and decision |
| --- | --- |
| Open | In a local desktop terminal, an interface choice offers terminal or browser; `--terminal` and `--server` select directly. `--server --no-open` prints the private local URL. The browser starts on an available loopback port. |
| Select scope | The header's main menu creates a draft **New Environment** or opens a saved setup or recorded deployment. Each open environment gets a header tab. Switching the tab changes the settings, inventory, history, and action target; tab changes wait until an operation finishes or stops. A deployment is marked recorded by a matching successful apply receipt. |
| Unlock | The browser requests a local vault password once at startup. On a fresh vault it asks to create and confirm one; an existing vault is unlocked without resetting it. The Pulumi stack passphrase is a separate secret on first use. The browser session reuses the vault unlock across actions and locks after 20 minutes of inactivity. |
| Choose action | The selected environment's Actions view has described cards for Preview, Preview and deploy, setup, status, report, GitHub setup, environment removal, and GitHub teardown. Drift is launched from Overview; project-wide removal is in the main menu when a shared discovery stack exists. |
| Configure | Settings is a grouped, editable whole form: target, AWS, project inputs, optional GitHub settings, and credentials. It starts with saved/default values, computes derived input previews, validates edits, and returns field-specific errors while preserving entries. AWS SSO profile setup/sign-in and target checks precede accepting a target. Existing account, region, and backend remain bound to its saved scope. |
| Prepare and preview | The CLI verifies AWS identity and state, optionally bootstraps a state bucket, prepares Pulumi and a cached Lambda archive, and saves a Pulumi plan. The browser can display the last report as **unchecked** before connecting, then state inventory and proposed changes. Preview exits without apply. |
| Review and apply | The plan highlights deletion/replacement before other changes. A deploy requires explicit confirmation; destructive operations require the exact stack name, and CI refuses destructive plans. Before `pulumi up --plan`, the CLI rechecks the saved plan, archive, and deployment-input digests. A successful apply records allowlisted outputs, an apply receipt, a report, and optional readiness/discovery publication. |
| Finish | The result offers a return to Actions in the same session. Environment and project teardown have staged intent/effect/name confirmation, retire discovery before destruction where configured, and keep shared/preexisting ownership distinct. |

Evidence: [mode and browser launch](https://github.com/lambdawalker/go.infra.composer/blob/ff065d4b853c7b0a2981da342767a569f18633fb/deploycli/cmd/infra-deploy/main.go#L361-L421), [environment records and tabs](https://github.com/lambdawalker/go.infra.composer/blob/ff065d4b853c7b0a2981da342767a569f18633fb/deploycli/cmd/infra-deploy/browser_environments.go#L39-L127), [form construction and validation](https://github.com/lambdawalker/go.infra.composer/blob/ff065d4b853c7b0a2981da342767a569f18633fb/deploycli/cmd/infra-deploy/form.go#L31-L209), [connect and prepare](https://github.com/lambdawalker/go.infra.composer/blob/ff065d4b853c7b0a2981da342767a569f18633fb/deploycli/cmd/infra-deploy/main.go#L941-L1136), [preview and apply](https://github.com/lambdawalker/go.infra.composer/blob/ff065d4b853c7b0a2981da342767a569f18633fb/deploycli/cmd/infra-deploy/main.go#L1213-L1365), [teardown](https://github.com/lambdawalker/go.infra.composer/blob/ff065d4b853c7b0a2981da342767a569f18633fb/deploycli/cmd/infra-deploy/main.go#L1164-L1210).

## Interface anatomy and artifact evidence

The browser uses a workspace header with a main menu, open **environment tabs**, repository link, and System/Light/Dark theme control. A resizable left pane holds progress and deployment context. The center has **Actions, Settings, Overview, Topology, Process output** views. The right pane holds selected artifact details and a searchable, filterable hierarchy. A fixed bottom bar holds the current action and countdown; blocking questions, vault unlock, sign-in, and destructive reviews use dialogs. The topology and artifacts share the report data, including parent/dependency links, owner/feature labels, AWS icons, and selection. The bundle is served locally with no CDN. [HTML structure](https://github.com/lambdawalker/go.infra.composer/blob/ff065d4b853c7b0a2981da342767a569f18633fb/deploycli/internal/wizardweb/ui/index.html#L19-L153) · [environment tab behavior](https://github.com/lambdawalker/go.infra.composer/blob/ff065d4b853c7b0a2981da342767a569f18633fb/deploycli/internal/wizardweb/ui/environment-menu.js#L149-L205) · [workspace routing](https://github.com/lambdawalker/go.infra.composer/blob/ff065d4b853c7b0a2981da342767a569f18633fb/deploycli/internal/wizardweb/ui/workspace.js#L398-L456)

Overview separates previously recorded state, a prepared plan, drift, and deployment history. Cached artifacts are marked unchecked until state is read; Pulumi state is explicitly described as recorded presence, not a live AWS check. Plan entries are capped in the visual list at 100 but retain the total and owner counts. Artifact details show supported before/after values and replacement fields, while history offers an HTML artifact-report download. Reports are also written as `artifacts.json`, `artifacts.md`, and `artifacts.html` under private local `reports/<environment>/<timestamp>/`; `report` and `drift` provide read/review paths without applying a deployment. Drift previews refresh and distinguishes changed, missing, unverified, and unchanged resources. [plan parsing/order](https://github.com/lambdawalker/go.infra.composer/blob/ff065d4b853c7b0a2981da342767a569f18633fb/deploycli/cmd/infra-deploy/plan.go#L19-L113) · [report generation](https://github.com/lambdawalker/go.infra.composer/blob/ff065d4b853c7b0a2981da342767a569f18633fb/deploycli/cmd/infra-deploy/reports.go#L104-L265) · [drift](https://github.com/lambdawalker/go.infra.composer/blob/ff065d4b853c7b0a2981da342767a569f18633fb/deploycli/cmd/infra-deploy/drift.go#L65-L155) · [history download](https://github.com/lambdawalker/go.infra.composer/blob/ff065d4b853c7b0a2981da342767a569f18633fb/deploycli/internal/wizardweb/history.go#L48-L81).

## Credentials and session boundaries

The server binds `127.0.0.1` on a random port. The printed URL carries a random token in its fragment, moved into tab session storage; API calls require a bearer token. The handler checks Host/Origin, restricts cross-site requests, and sends no-store/CSP/referrer headers. A wizard index under `~/.infra-composer/_wizards/` records a process and instance ID without a session token. The browser vault holds an in-session verifier and passphrase until idle lock or session end. Cloudflare/GitHub tokens live in a separate locally encrypted `credentials.bin` for the selected project/environment; password fields show a saved placeholder and blank means retain the existing value. The implementation does **not** implement Bitwarden export or generated passphrases; those are requirements learned from the Android setup work, not existing Composer behavior. [server/session](https://github.com/lambdawalker/go.infra.composer/blob/ff065d4b853c7b0a2981da342767a569f18633fb/deploycli/internal/wizardweb/server.go#L32-L210) · [idle lock](https://github.com/lambdawalker/go.infra.composer/blob/ff065d4b853c7b0a2981da342767a569f18633fb/deploycli/internal/wizardweb/vault.go#L14-L169) · [credential storage](https://github.com/lambdawalker/go.infra.composer/blob/ff065d4b853c7b0a2981da342767a569f18633fb/deploycli/cmd/infra-deploy/credentials.go#L18-L145).

## Reusable wizard prompt lessons

1. Identify the deployable unit before choosing the main tabs. Composer's tabs are **environments** because every action, stack, report, and saved target is scoped to one environment. A different CLI, such as Android repository setup, may instead need **module tabs**. The center view tabs are subordinate to the selected target.
2. Preserve the real CLI operations and their effects. Make Actions immediately discoverable for the selected target, with card descriptions that explain inputs, reviews, and side effects. Do not add a redundant selection screen before the target's actions.
3. Gather compatible inputs in one form, group them by purpose/action, prefill saved and derived nonsecret defaults, and show a shared field only once. Mark saved credentials without revealing them. Keep field values on validation or cloud-check failure; ask a one-off question only when it cannot be prepared in the form.
4. Model evidence states separately: cached report (unchecked), state inventory, live drift result, proposed plan, approved saved plan, and successful apply receipt. Keep operations and artifacts scoped to the selected tab. Explain limits, ownership, and destructive consequences at the point of decision.
5. Reuse a vault unlock across actions until the actual inactivity deadline. Handle creation/unlock in a dialog and lock the workspace in place. Generated credentials and external exports, when a consumer CLI needs them, require their own reviewed design; Composer does not supply those features.

## Preview feasibility

**Local capture recipe:** From a **consumer repository root** with `deploy.json`, its Pulumi program, and a pinned launcher/installed CLI, run `infra-deploy --server --no-open` (or that repository's `./deploy.sh --server --no-open` / `deploy.bat --server --no-open`). Open the printed loopback URL in a browser on that computer. Capture (1) the startup vault dialog, (2) the selected environment's header tabs and Actions cards, and, if saved records exist, (3) Settings, Overview's clearly marked cached inventory, artifact details, and Topology. Do not start Preview, Deploy, or teardown merely to obtain screenshots: Preview can prepare a stack or state bucket, while Apply and removal change remote resources. End the local server with Ctrl+C.

Completing settings, preview, drift, or apply needs the relevant local vault, AWS/Pulumi tools, account access, and possibly GitHub/Cloudflare credentials. This source repository itself has no root `deploy.json` or ready-to-run browser demo; the committed JS/CSS/HTML are embedded by the Go server, and its renderer `npm run build` only rebuilds the vendored topology runtime. A deterministic full-state preview would require an explicit mocked-state fixture. No standalone visual-preview command is documented. In this study run, no screenshot was generated: the cloud browser cannot reach the authenticated loopback URL, and a local Chromium executable was unavailable.
